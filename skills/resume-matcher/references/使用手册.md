# 简历岗位匹配 Skill — 使用手册（通用版 v2.0）

> 配套：`scripts/run.sh`（简历匹配一键） / `scripts/parse_job.py`（岗位拆解） / `scripts/resume_toolkit.py`（主程序） / `scripts/jobs_lib.py`（岗位库）

---

## 零、两条工作流总览

```
工作流 A（岗位入库）：人事发岗位JD → parse_job.py 规则拆解 → AI复核补全特征词 → 写入 jobs_lib.py
工作流 B（简历匹配）：简历丢进简历库 → run.sh 一键运行 → 输出打分 Excel
```

岗位库（jobs_lib.py）是 A 和 B 的衔接点：A 维护岗位特征，B 按特征打分。

---

## 一、工作流 A：岗位 JD 颗粒度拆解入库

### 步骤

```bash
# 1. 规则拆解（自动提取基础字段，只预览不写入）
python3 scripts/parse_job.py "<岗位JD文本>" --name "岗位名称"

# 2. 复核补全特征词（AI 或人工，重点补 hard/skill/industry/duty）

# 3. 确认后写入岗位库
python3 scripts/parse_job.py "<岗位JD文本>" --name "岗位名称" --add
```

### 拆解产物（对应 jobs_lib.py 岗位 dict）

| 字段 | 来源 | 示例 |
|---|---|---|
| `code` | 用户提供或自动生成 P001… | A69663 |
| `name/line/salary` | 规则提取 + 人工补 | Codex技能开发工程师 |
| `edu` | 规则提取（本科/大专/…） | 本科 |
| `exp_years` | 规则提取（3-5年 → 3） | 3 |
| `hard` | **AI 复核重点**：一票否决条件 | ["外单"] |
| `industry` | 规则提取 + 复核精简 | 内衣/电商 |
| `skill` | 规则提取 + **AI 补独有技能词** | Codex/Python/爬虫 |
| `duty` | 规则提取（动词+名词） | 自动化/提效/培训 |

### 拆解质量建议

- **hard 宁少勿滥**：只放真正"没有就不行"的条件（如英语四级、某平台 3 年经验），放多了会误杀优秀候选人
- **skill 宁全勿缺**：把 JD 里出现过的工具/平台/方法全收进来，命中的词越多越能区分真假
- **industry 控制 5-10 个**：保留强相关行业词，避免通用词稀释

## 二、工作流 B：简历匹配

```bash
# 简历 PDF/TXT/DOCX 丢进简历库目录后，一键运行：
bash scripts/run.sh [简历目录] [输出目录]
# 输出：输出/简历岗位匹配结果.xlsx（匹配矩阵 + 匹配明细 + 推荐摘要）
```

详细步骤见下节「5 步工作流」。

---

## 三、为什么需要这套流程

HR 每天面对大量简历 PDF，人工逐份读 → 逐岗比 → 手写判断，平均一份 5-10 分钟。这套工具把流程压缩为：

```
收简历 → 丢进简历库目录 → 运行一条命令 → 得到打分排序 Excel
```

第一次运行约 1 分钟（含依赖安装），之后每次 30 秒左右（取决于简历数量）。

---

## 三、5 步工作流

| 步骤 | 动作 | 耗时 | 工具/说明 |
|---|---|---|---|
| 1 | 收集简历，统一放进简历库目录（支持子文件夹） | — | 支持 PDF / TXT / DOCX |
| 2 | 运行 `bash scripts/run.sh` | ~30秒/100份 | 自动解析全部简历 |
| 3 | 打开输出的「推荐摘要」表 | 1分钟 | 每候选人 → 推荐岗位 + 分数 |
| 4 | 「匹配矩阵」表按岗位列看候选人分数排名 | 2分钟 | 70+ 重点关注 / 55+ 备选 / <55 暂不匹配 |
| 5 | 对进入初筛的候选人，回看「匹配明细」中的命中词与差距，安排面试 | — | 命中词可直接作为面试追问点 |

## 四、打分规则（透明可解释）

总分 **100 分** = 6 个维度加权，每份简历对 10 个岗位各出一份分数。**同一份简历在不同岗位的分数不同**——这是"人岗匹配"而不是"简历好坏"。

| 维度 | 分值 | 判定逻辑 |
|---|---|---|
| 学历匹配 | 10 | 达到岗位要求满分；差一级 6 分；差两级 3 分 |
| 经验年限 | 20 | 按简历时间跨度/明确年限估算；达到要求满分，差 1 年 15 分，差 2 年 10 分 |
| 行业经验 | 20 | 命中岗位行业关键词比例（内衣/服装/跨境/电商…） |
| 技能匹配 | 25 | 命中岗位技能关键词（ET/直通车/Python/AQL…），权重最高 |
| 职责覆盖 | 15 | 命中岗位职责关键词（批办/驻厂/爆款…） |
| 硬性条件 | 10 | 岗位硬性词全中才满分（如 A56129 的"外单"） |

> 命中与未命中词都会写进 Excel，方便跟候选人沟通时直接引用，也方便按实际招聘标准调整关键词。

## 六、常见问题

### 1. 扫描件简历（图片型 PDF）
工具会提示"PDF 无文本层，需 OCR"。两种处理：
- 用 WPS/Adobe 的"文字识别"另存为文本型 PDF；
- 或把识别文本存成 `.txt` 放入简历库（工具支持 TXT）。

### 2. 想更智能（语义级理解）
当前为规则打分（无需联网、数据不出本地）。如需要，可扩展为"规则初筛 + 大模型复核"两段式：规则先捞人，LLM 只对 55 分以上候选人出深度评估（动机、匹配理由、风险点）。

### 3. 新增/修改岗位
在 `jobs_lib.py` 按现有格式加一条 `dict`，填好行业词/技能词/职责词/硬性词即可。改完重跑脚本自动生效；需要同步更新岗位汇总 Excel 时运行 `python3 scripts/build_jobs_excel.py`。

---

## 七、合规提醒（必读）

- 简历含个人敏感信息，**工具全程在本机运行，不会上传任何数据**；
- 批量处理涉及个人信息，建议在内部环境运行，结果文件仅限招聘相关人员访问；
- 初筛结果只作辅助排序，**最终录用判断需人工复核**，避免因关键词缺失误判优秀候选人（例如"外单"写成"外贸订单"这类同义表达）。
