# 简历岗位匹配（resume-matcher）· 通用版

> **Goal**: 一条完整 HR 招聘初筛流水线——**岗位 JD 拆解入库** + **简历批量匹配打分**，全部一条命令/一次对话完成。不再绑定任何特定公司岗位，JD 随发随拆、简历随到随匹。

## When to Use

用户提出以下需求时触发本 Skill：
- **岗位侧**："这个岗位帮我拆一下 / 岗位信息整理入库 / 发你一个 JD / 新岗位加进库里"
- **简历侧**："帮我处理简历 / 筛选简历 / 人岗匹配 / 匹配度打分 / 谁适合某个岗位"
- **综合**："我是 HR 怎么提效 / 帮我搭招聘初筛流程"

## When NOT to Use

- 用户只是闲聊招聘话题，不涉及具体 JD 或简历文件
- 单份简历的深度人工评估（工具做初筛，深度评语另行处理）

## 工作流 A：岗位入库（岗位 JD → 结构化特征）

```
用户发来岗位（文字 / 截图 / 链接）
    │
    ▼
1. 拿到 JD 文本：
   - 文字 → 直接用
   - 截图 → AI 读取图片提取文字
   - 链接 → 尝试抓取；BOSS 直聘等平台有风控，抓不到就请用户贴文本
    │
    ▼
2. 规则拆解（自动提取基础字段）：
   bash scripts/parse_job.py "<JD文本>" --name "岗位名称" [--code 编号]
   → 自动提取：薪资 / 学历 / 经验年限 / 行业词 / 技能词 / 职责词 / 硬性条件候选
    │
    ▼
3. AI 复核补全（关键步骤，决定打分质量）：
   - hard：岗位一票否决条件（如"外单""英语四级""XX平台经验"）
   - skill：JD 独有的核心技能（词表外新词，如"Codex""AQL""引力魔方"）
   - industry：与岗位强相关的行业词
   - duty：职责关键词
    │
    ▼
4. 写入岗位库：python3 scripts/parse_job.py "<JD文本>" --name "..." --add
   （或 AI 直接编辑 scripts/jobs_lib.py）
    │
    ▼
5. 回复用户：岗位「XX」已入库，当前岗位库共 N 个岗位 ✅
```

**岗位编号**：用户提供则沿用（如 A56129）；否则自动生成 P001、P002…

**岗位库文件**：`scripts/jobs_lib.py` 的 `JOBS` 列表，每条 dict 字段：

| 字段 | 含义 | 示例 |
|---|---|---|
| `code/name/line/salary` | 编号/名称/业务线/薪资 | A69663 |
| `edu` | 学历要求 | 本科 |
| `exp_years` | 经验要求（年） | 3 |
| `hard` | 硬性条件（全命中才满分） | ["外单"] |
| `industry` | 行业关键词 | 内衣/电商/跨境… |
| `skill` | 技能关键词（权重最高） | Codex/Python/爬虫… |
| `duty` | 职责关键词 | 自动化/提效/培训… |
| `fresh` | 校招模式开关（可选，=1 时应届优先、老手降权） | 1 |

> **校招岗注意事项**：应届校园招聘类岗位请在 dict 中加 `fresh=1`，否则打分会把资深老手排在应届生前面（默认逻辑是社招向的）。示例见岗位 `DZ01`（国内电商运营助理·应届校招）。

## 工作流 B：简历匹配（简历库 → 打分排序）

### 一键运行（推荐）

```bash
bash /root/.codebuddy/skills/resume-matcher/scripts/run.sh [简历目录] [输出目录]
```

流程：
1. 用户把简历 PDF/TXT/DOCX 放入简历库目录（支持子文件夹；也支持直接在对话里发简历，AI 代为入库）
2. 运行 `run.sh`（自动装依赖、自动定位简历目录）
3. 输出「简历岗位匹配结果.xlsx」，向用户汇报：每人最佳岗位 + 分数 + 命中/缺失点

### 命令参数

| 参数 | 说明 | 默认 |
|---|---|---|
| `--resume-dir` | 简历目录 | 脚本同目录 `简历库/` |
| `--out-dir` | 输出目录 | 脚本同目录 `输出/` |
| `--out-file` | 输出文件名 | `简历岗位匹配结果.xlsx` |

> `run.sh` 不传参时自动优先使用 `/workspace/hr-resume-matcher/简历库`（若存在），否则用 Skill 内置 `data/简历库`。

### 输出解读（3 张表）

| 工作表 | 内容 | 用途 |
|---|---|---|
| **匹配矩阵** | 每候选人 × 每岗位分数 + 最高匹配岗位 | 按岗位列看排名 |
| **匹配明细** | 6 维度分 + 命中/未命中关键词 | 面试追问点 |
| **推荐摘要** | 每候选人 Top3 岗位 + 总分 + 联系方式 | 快速捞人 |

**分档**：总分 100（学历10 + 经验20 + 行业20 + 技能25 + 职责15 + 硬性10）
- ≥ 70 分 → 重点关注约面 / 55–69 备选 / <55 暂不匹配

## 工作流 C：BOSS 直聘简历 ZIP 自动导入

> 解决"BOSS 简历要逐份手动下载"的痛点：**下载这一步用 BOSS 官方批量导出**（不冒自动化点击的封号风险），解压识别入库交给工具。

### BOSS 端操作（官方批量导出，约 1 分钟）

```
登录 BOSS 直聘企业版网页端 www.zhipin.com/enterprise/
→ 人才库 / 沟通中 页面
→ 勾选简历（可"全选本页"）
→ 右上角【下载简历】→ 选 PDF 格式
→ 系统自动打包 ZIP 下载（每次最多 100 份）
```

### 工具导入（一条命令）

```bash
python3 scripts/import_boss_zip.py /path/to/boss_简历.zip
# 或指定目录下所有 ZIP：
python3 scripts/import_boss_zip.py /path/to/下载目录/
# 导入后自动跑匹配：
python3 scripts/import_boss_zip.py xxx.zip --run
```

自动完成：**解压 → 识别姓名/求职意向 → 重命名（姓名-意向.pdf）→ 入库 → （可选）匹配**。

> 若个别简历姓名未识别（正文无姓名线索），导入报告会标注"姓名未识别"，手动改名即可，不影响匹配打分。

## 工作流 C-2：BOSS 推荐/沟通页候选人一键抓取（CDP 直连，无需简历 URL）

> 背景：BOSS 新版网页端是 SPA + iframe 结构，候选人卡片渲染在 `zhipin.com/web/frame/recommend/?jobid=...` 内嵌 iframe，点候选人地址栏不产生独立简历 URL——按 URL 抓取的模式失效。改用 CDP 直连本地已登录 Chrome，读 iframe DOM 批量提取候选人。

前置（一次性）：
1. 调试模式启动 Chrome（独立 profile）：`chrome.exe --remote-debugging-port=9222 --user-data-dir="C:\chrome_boss_profile"`
2. 弹出的 Chrome 登录 BOSS 直聘企业版，打开「推荐牛人」或「沟通」列表页
3. 保持该浏览器开着

用法：
```bash
python3 scripts/capture_boss_feed.py                  # 抓当前页全部候选人 → data/简历库
python3 scripts/capture_boss_feed.py --run            # 抓取后自动跑岗位匹配
```

每张候选人卡片会结构化成一份 TXT（姓名/年龄/学历/经验/期望/优势全文/技能标签/工作经历/教育经历），命名「姓名.txt」入库，可直接参与打分。已存在同名自动跳过（`--no-skip-existing` 可强制覆盖）。

## 岗位库维护

- **新增岗位**：优先走工作流 A（parse_job.py + AI 复核）；也可直接在 jobs_lib.py 加一条 dict
- **删除/修改岗位**：编辑 jobs_lib.py 后重跑简历匹配即生效
- **岗位库变更后**：可选 `python3 scripts/build_jobs_excel.py` 重新生成岗位汇总 Excel
- **内置示例**：jobs_lib.py 保留 10 个润微岗位作为示例（覆盖技术/质量/电商/达人/AI 多业务线）+ DZ01 国内电商运营助理（应届校招，当前主招），可作为新岗位特征词的参考模板；不需要可随时删

---

## 注意事项

1. **JD 来源**：BOSS 直聘等平台链接大概率被风控拦截，优先让用户贴文本或发截图
2. **规则拆解是建议稿**：parse_job.py 提取的行业/技能词只做初稿，**AI 复核补全 hard/skill 是决定打分质量的关键**，不要跳过
3. **扫描件 PDF**：提示"需 OCR"时，先用 WPS/Adobe 文字识别另存，或把识别文本存 .txt
4. **规则打分局限**：同义表达可能漏判（如"外单"vs"外贸订单"）；初筛只作排序，**录用判断需人工复核**
5. **合规**：简历含敏感个人信息，全程本机运行、数据不上传；结果文件仅限招聘相关人员访问
